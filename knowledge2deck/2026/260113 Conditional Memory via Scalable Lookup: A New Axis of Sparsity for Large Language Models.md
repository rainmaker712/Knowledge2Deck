[260113 Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models](https://www.arxiv.org/abs/2601.07372)

Authors: Xin Cheng, Wangding Zeng, Damai Dai, Qinyu Chen, Bingxuan Wang, Zhenda Xie, Kezhao Huang, Xingkai Yu, Zhewen Hao, Yukun Li, Han Zhang, Huishuai Zhang, Dongyan Zhao, Wenfeng Liang

> While Mixture-of-Experts (MoE) scales capacity via conditional computation, Transformers lack a native primitive for knowledge lookup, forcing them to inefficiently simulate retrieval through computation. To address this, we introduce conditional memory as a complementary sparsity axis, instantiated via Engram, a module that modernizes classic N-gram embedding for O(1) lookup. By formulating the Sparsity Allocation problem, we uncover a U-shaped scaling law that optimizes the trade-off between neural computation (MoE) and static memory (Engram). Guided by this law, we scale Engram to 27B parameters, achieving superior performance over a strictly iso-parameter and iso-FLOPs MoE baseline. Most notably, while the memory module is expected to aid knowledge retrieval (e.g., MMLU +3.4; CMMLU +4.0), we observe even larger gains in general reasoning (e.g., BBH +5.0; ARC-Challenge +3.7) and code/math domains~(HumanEval +3.0; MATH +2.4). Mechanistic analyses reveal that Engram relieves the backbone's early layers from static reconstruction, effectively deepening the network for complex reasoning. Furthermore, by delegating local dependencies to lookups, it frees up attention capacity for global context, substantially boosting long-context retrieval (e.g., Multi-Query NIAH: 84.2 to 97.0). Finally, Engram establishes infrastructure-aware efficiency: its deterministic addressing enables runtime prefetching from host memory, incurring negligible overhead. We envision conditional memory as an indispensable modeling primitive for next-generation sparse models.

## Follow-Up Questions

1. Engram introduces O(1) lookup as a "conditional memory" primitive separate from neural computation. Why does the standard Transformer architecture lack an efficient native knowledge retrieval mechanism, and what computational properties of attention make it a poor substitute for direct lookup?

2. The paper proposes the "Sparsity Allocation" problem and finds a U-shaped scaling law between neural computation (MoE) and static memory (Engram). What does the U-shape imply about the relationship between these two forms of capacity — is there a principled reason why both extremes (pure MoE and pure static memory) are suboptimal?

3. Engram shows unexpected gains in reasoning and code/math (+5.0 BBH, +3.0 HumanEval) beyond the expected knowledge retrieval improvements. The mechanistic explanation is that it "relieves early layers from static reconstruction." What does this mean concretely, and why would freeing early layers improve complex reasoning rather than just factual recall?

4. By "delegating local dependencies to lookups," Engram frees attention capacity for global context, leading to gains on long-context retrieval (NIAH: 84.2 → 97.0). What is the distinction between "local" and "global" dependencies in this context, and why is attention particularly ill-suited to handle local n-gram-style dependencies efficiently?

5. Engram uses "deterministic addressing" to enable runtime prefetching from host memory. What makes deterministic addressing possible for a learned lookup module, and how does this differ from the non-deterministic access patterns of standard attention or sparse MoE routing?

6. The paper scales Engram to 27B parameters and achieves better performance than an iso-parameter, iso-FLOPs MoE baseline. What does "iso-FLOPs" mean in this comparison, and why is it important to control for both parameters and FLOPs separately when evaluating a new sparsity axis?

7. What are the key limitations of the conditional memory approach — for instance, how does Engram handle knowledge that requires contextual interpretation (e.g., polysemous words), and what types of reasoning tasks would you expect it to fail on even with a very large memory?


## Answers

**1.** Standard Transformers lack an efficient native knowledge retrieval mechanism because attention is fundamentally a dense, compute-intensive operation: every query must attend to every key in the context (or a learned subset), and storing factual knowledge requires that knowledge to be implicitly encoded in the weight matrices through gradient-based learning. This means "retrieving" a fact requires running a full forward pass through multiple layers rather than a direct address lookup. Attention is a poor substitute for lookup because it scales quadratically with sequence length, requires the fact to be reconstructable from the current context (adding computational load to early layers), and cannot directly address a persistent external store — it can only attend over the active context window, not over a separate static memory bank with O(1) access.

**2.** The U-shaped scaling law implies that the two forms of capacity are complementary but not substitutable beyond their respective domains of competence. Pure MoE (maximum neural computation, minimum static memory) is suboptimal because a significant fraction of the model's parameters must be used to memorize static n-gram-level patterns that don't require reasoning — wasting compute on what a lookup table could do trivially. Pure static memory (maximum Engram, minimum neural computation) is suboptimal because complex reasoning, long-range dependency resolution, and compositional inference require dynamic neural computation that a fixed lookup table cannot provide. The U-shape reflects that the optimal model allocates each type of work to the mechanism best suited for it: static knowledge to memory, dynamic reasoning to neural compute.

**3.** "Relieving early layers from static reconstruction" means that in standard Transformers, early layers must process each token to first identify n-gram patterns and surface-level linguistic features — a preprocessing step that rebuilds local context before higher layers can reason. When Engram handles these local, surface-level lookups directly, early transformer layers are free to begin abstract, relational processing sooner in the network depth, effectively giving the model more "reasoning depth" per layer. This is why the gains appear not just in factual recall but in BBH (which requires multi-step reasoning): the backbone has access to higher-quality intermediate representations earlier in the forward pass.

**4.** "Local dependencies" are short-range, surface-level patterns — collocations, common phrases, syntactic bigrams or trigrams — predictable from a few adjacent tokens without needing global context. "Global dependencies" are long-range semantic and coreference relationships requiring attention across distant positions. Attention is ill-suited to local n-gram dependencies because it applies the same quadratic mechanism to both local and global patterns indiscriminately, and softmax normalization forces attention weights to be distributed across all positions — meaning local patterns compete with globally relevant tokens for attention head capacity. Offloading local patterns to Engram lookups leaves attention to specialize on global, context-sensitive dependencies it is uniquely suited to handle.

**5.** Deterministic addressing is possible for Engram because its lookup keys are derived from the current n-gram of input tokens — a function purely of the input sequence, not of learned routing weights or dynamic context-dependent scores. Given the input tokens, the address into the Engram memory table is fully determined before any computation, allowing the hardware to prefetch relevant memory entries from host DRAM into cache before the computation needs them. This contrasts with standard attention (query-key dot products must be computed first) and sparse MoE routing (token-to-expert assignments depend on learned routing logits computed mid-forward-pass), both of which have non-deterministic access patterns that make hardware prefetching impossible.

**6.** "Iso-FLOPs" means the comparison baseline (MoE) is constructed to use the same number of floating point operations per forward pass as the Engram model, not just the same number of parameters. This distinction matters because Engram achieves part of its parameter count through a large static memory table requiring only O(1) lookups (very few FLOPs per access) rather than additional weight matrices requiring dense matrix multiplications. Controlling for FLOPs separately from parameters ensures that any performance advantage of Engram is not simply due to doing more computation per example, while the parameter control ensures it is not just from having more total capacity.

**7.** The key limitation of conditional memory is that it is fundamentally a surface-form lookup: Engram indexes memory by n-gram patterns, so for polysemous words or context-dependent expressions the lookup may return a representation that blends over different senses rather than selecting the contextually appropriate one — contextual disambiguation still depends on the neural backbone. Tasks where Engram would likely fail even at very large scale include: (a) tasks requiring compositional reasoning over novel combinations of familiar concepts not seen in the training n-gram distribution; (b) tasks requiring tracking of dynamic state across a long context (e.g., multi-hop reasoning where intermediate conclusions must be carried forward); and (c) tasks where relevant knowledge is expressed in radically different surface forms across instances, making it hard for the n-gram address to reliably retrieve the right memory entry.

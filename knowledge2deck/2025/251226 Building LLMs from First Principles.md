## Follow-Up Questions

1. What are the fundamental architectural decisions that must be made when building an LLM from scratch — such as tokenization strategy, attention mechanism, and positional encoding — and how do these choices interact with each other?

2. When building from "first principles," how do you decide which established practices (e.g., pre-LayerNorm vs. post-LayerNorm, RoPE vs. learned embeddings) to adopt versus which to derive independently through experimentation?

3. What does it mean to truly understand a component of an LLM "from first principles" as opposed to treating it as a black box? How would you test whether your understanding is deep enough to make principled modifications?

4. How do the engineering constraints of distributed training (data parallelism, tensor parallelism, pipeline parallelism) force architectural decisions that might differ from what you'd design if running on a single device?

5. What role does the choice of loss function and optimizer play in defining what an LLM "learns," and are there alternatives to cross-entropy + AdamW that could lead to fundamentally different model behaviors?

6. When building an LLM from first principles, how do you handle the feedback loop between data quality, model architecture, and evaluation — given that you can't fully evaluate capabilities until the model is trained?

7. What are the most common misconceptions practitioners have about how LLMs work internally, and which of these could only be resolved by building one from scratch rather than fine-tuning an existing model?

## Answers

**1.** The core architectural decisions — tokenizer vocabulary size, attention type (full vs. grouped-query vs. sliding window), positional encoding (RoPE, ALiBi, or learned), and normalization placement — are deeply interdependent. For example, vocabulary size affects sequence length for the same semantic content, which in turn influences how expensive attention is and how much positional signal is needed. RoPE naturally integrates with grouped-query attention (GQA) because both operate in the per-head dimension space, whereas learned absolute embeddings create hard length ceilings that conflict with variable-length pre-training. Choosing a subword tokenizer (BPE, SentencePiece) versus character or byte-level approaches also changes what the model must learn — byte-level avoids out-of-vocabulary issues but requires the model to learn more compositional patterns from scratch.

**2.** When building from first principles, established practices that have been empirically validated at scale — such as pre-LayerNorm (for stable training gradients), RoPE (for length generalization), and SwiGLU activations (for improved loss curves) — are generally adopted because re-deriving them experimentally would require substantial compute. The principled approach is to understand *why* each choice works before adopting it: pre-LayerNorm prevents gradient explosion by normalizing before the residual is added to the stream; RoPE encodes relative position through rotation in complex space, which generalizes to unseen lengths. Experimentation is most valuable at the margins — e.g., testing whether a specific mixture of attention window sizes and full attention layers works better for your target context length than a published recipe designed for a different scale.

**3.** Truly understanding a component from first principles means being able to predict its failure modes, know when to replace it, and implement it correctly from scratch without reference to existing code. For attention, this means understanding why causal masking is needed for autoregressive generation, what happens when query and key norms diverge (attention entropy collapse), and how KV cache memory scales with sequence length and batch size. A practical test of sufficient understanding: if you can write the forward and backward passes by hand, identify the numerical precision pitfalls (e.g., softmax overflow without temperature scaling), and predict performance degradation when the component is used outside its design assumptions, your understanding is likely deep enough to make principled modifications.

**4.** Distributed training imposes significant architectural constraints. Tensor parallelism requires the model's weight matrices to be divisible across devices, which constrains head counts and hidden dimensions to multiples of the device count (often 8 or 16). Pipeline parallelism introduces micro-batch scheduling that effectively requires layers to be computationally balanced, discouraging architectures with heterogeneous layers. Data parallelism with gradient accumulation means the effective batch size can be very large, which may require a warm-up learning rate schedule and influences choices like weight decay. These constraints mean that a model designed for single-device training (e.g., with irregular layer sizes or asymmetric attention patterns) would often be redesigned to have uniform, divisible layer widths when scaling to hundreds of GPUs.

**5.** Cross-entropy loss with next-token prediction defines learning as conditional distribution matching over a discrete vocabulary — the model learns to assign probability mass to tokens consistent with training data patterns. Alternatives such as sequence-level contrastive losses (e.g., InfoNCE) would shift learning toward distinguishing good sequences from bad ones, potentially producing different generalization behavior. The choice of AdamW specifically matters because its decoupled weight decay regularizes parameter magnitude without interfering with adaptive learning rates, and its first and second moment estimates implicitly adjust per-parameter learning rates — without this, language model training is empirically much more unstable. Alternative optimizers like Muon (orthogonalized gradient descent) or Sophia (second-order methods) change the loss landscape traversal and may produce models with different parameter magnitude distributions, though whether this leads to fundamentally different capabilities is still an active research question.

**6.** The feedback loop between data, architecture, and evaluation is managed through staged development: small proxy models (tens of millions of parameters) trained on data subsets are used to evaluate data curation strategies (deduplication, quality filtering, domain mix), and these proxies also serve as ablation beds for architectural choices like head count and FFN ratios. Evaluation before full training is done through perplexity on held-out data (which correlates with downstream capability though imperfectly), intermediate checkpoints evaluated on smaller benchmarks, and loss curve analysis for training stability signals. However, emergent capabilities that only appear at scale remain difficult to predict from small proxies, making the feedback loop inherently incomplete and requiring some degree of risk-taking in large training runs.

**7.** Common misconceptions include: (1) that attention "looks up" information like a database when in fact it computes weighted averages that blend all values simultaneously; (2) that the residual stream is a simple summation when it actually functions as a high-dimensional communication bus where layers read and write specialized subspaces; (3) that fine-tuning "teaches" the model new facts when it primarily adjusts existing representations and behavioral preferences. Building from scratch uniquely resolves the misconception about layer interactions — practitioners who only fine-tune often believe later layers do most of the "reasoning," but building and training a model from scratch with probing experiments reveals that early layers handle syntax and token statistics while middle layers encode factual associations, and late layers handle output formatting and style.

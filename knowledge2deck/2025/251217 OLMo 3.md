[OLMo 3](https://arxiv.org/abs/2512.13961)

Authors: Team OLMo (Allen Institute for AI, 70+ contributors)

> 완전 공개(fully-open) 언어 모델 패밀리 — 가중치뿐 아니라 모든 학습 단계, 체크포인트, 데이터 포인트, 의존성을 공개한다. OLMo 3 Think 32B는 "현재까지 출시된 가장 강력한 완전 공개 사고 모델"로 평가된다.

- **완전 공개 원칙**: 단순 가중치 공개(Llama, Mistral)와 달리 전체 파이프라인 공개 — 데이터 오염 감사, 학습 역학 연구, 독립 재현이 가능한 유일한 대형 모델 패밀리
- **4단계 파이프라인**: 사전학습(DOLMA 3; 7B: 6T 토큰) → SFT → DPO(선호 정렬) → Zero-shot RL(수학·코딩·명령 수행 특화 도메인)
- **Think 32B**: 확장된 추론(extended thinking) 능력 — test-time compute 스케일링 기반 추론 체인 생성과 RL 기반 추론 강화의 결합으로 추정
- **성능**: MMLU 7B ~70%, 32B ~80% — 완전 공개 데이터(DOLMA 3)만 사용하는 구조적 제약 하에서 동일 규모 독점 모델 대비 소폭 뒤처지나 투명성-성능 트레이드오프의 의도적 선택
- **멀티 능력 커버리지**: 장문 컨텍스트 추론, 함수 호출, 코딩, 명령 수행, 일반 대화, 지식 회상을 단일 모델 패밀리로 타겟

## Follow-Up Questions

1. 4단계 학습 파이프라인에서 SFT → DPO → RL의 순차적 적용이 왜 필요한가? DPO만으로 정렬이 충분하지 않은 이유는 무엇이며, 최종 RL 단계가 어떤 성능 격차를 메우는가?

2. OLMo 3 Think 32B의 "확장된 추론 능력"은 구체적으로 어떤 아키텍처적 또는 학습 방법론적 차별점에서 비롯되는가?

3. 7B 모델에 6T 토큰을 사용하면서 32B 변형에는 100B 토큰만 사용한 이유는 무엇인가? Chinchilla 스케일링 법칙에 따르면 32B 모델에는 훨씬 더 많은 토큰이 필요한데, 이 비대칭적 토큰 할당의 설계 근거는 무엇인가?

4. "완전 공개" 원칙이 실제로 재현성(reproducibility)과 과학적 가치에 어떤 실질적 기여를 하는가? 단순히 가중치만 공개하는 모델과 비교했을 때 가능한 구체적인 연구 활용 사례는 무엇인가?

5. Zero-shot RL을 수학, 코딩, 명령 수행 등 특화 도메인에 적용했는데, 각 도메인별 보상 함수(reward function)는 어떻게 설계되었는가? 특히 명령 수행처럼 정답이 명확하지 않은 도메인에서 보상 신호의 품질과 신뢰성을 어떻게 확보하는가?

6. MMLU 기준 7B ~70%, 32B ~80%는 동일 파라미터 규모의 Llama 3.1, Qwen 2.5 등과 비교했을 때 어떤 위치에 있으며, 성능 격차가 존재한다면 그 원인은 어디에 있는가?

7. 장문 컨텍스트 추론과 함수 호출 능력을 동시에 타겟하는데, 다양한 타겟 능력을 하나의 모델에 통합할 때 발생하는 멀티태스크 간섭(multi-task interference) 문제를 어떻게 관리하는가?

## Answers

**1.** SFT는 모델에 명령-응답 형식과 기본적인 도움 행동을 학습시키지만, 인간 선호의 미묘한 차이(안전성, 응답 스타일, 세부 정확도)를 포착하기에는 한계가 있다. DPO는 선호 쌍(chosen/rejected) 비교를 통해 이러한 정렬 격차를 줄이지만, 수학 문제의 정답 여부나 코드 실행 성공처럼 검증 가능한 정답이 있는 도메인에서는 보상 신호가 더 명확한 RL이 효과적이다. 최종 RL 단계는 "Zero-shot RL"로 명시되어 있어, 별도의 few-shot 예제 없이 보상 함수만으로 특화 도메인의 성능을 끌어올린다. 이는 SFT/DPO가 일반적 정렬을 담당하고 RL이 특정 능력의 상한선을 높이는 분업 구조다.

**2.** "thinking model"이라는 명칭과 최근 추세를 고려하면, test-time compute 스케일링(추론 시 더 긴 사고 체인 생성)과 RL 기반 추론 강화의 조합일 가능성이 높다. OpenAI o1, DeepSeek-R1과 유사하게 모델이 최종 답변 전에 중간 추론 단계를 명시적으로 생성하도록 학습되었을 것이다. 기반 모델(OLMo 3 32B)과 동일한 아키텍처를 사용하되 후반 학습 단계에서 추론 특화 데이터와 보상 설계가 차별화되는 구조로 추정된다. (전문 확인 필요)

**3.** 32B 변형에 100B 토큰이라는 Chinchilla 최적 비율과의 괴리는, 해당 변형이 처음부터 학습된 것이 아니라 기존 체크포인트에서 추가 학습(continual pre-training)되었거나 특정 실험적 변형일 가능성을 시사한다. 반면 7B에 6T 토큰을 투입한 것은 over-training 전략으로, 추론 비용이 낮은 소형 모델의 성능을 극대화하려는 의도이며 Llama 3가 8B 모델에 15T 토큰을 사용한 것과 동일한 맥락이다. (전문에서 32B의 정확한 학습 설정 확인 필요)

**4.** 가중치만 공개하는 모델은 "무엇을 만들었는가"만 보여주지만, 전체 파이프라인 공개는 "어떻게, 왜 그렇게 만들었는가"를 보여준다. 구체적 활용 사례: (1) 데이터 오염(data contamination) 감사 — 벤치마크 데이터가 학습 데이터에 포함되었는지 직접 검증, (2) 학습 역학(training dynamics) 연구 — 중간 체크포인트를 통해 능력이 언제 출현하는지 추적, (3) 데이터 귀인(data attribution) — 특정 출력이 어떤 학습 데이터에서 비롯되었는지 분석, (4) 독립적 재현 — 동일 설정으로 학습을 재현하여 결과 검증. 이는 LLM 연구가 점점 블랙박스화되는 추세에 대한 과학적 대안이다.

**5.** 수학과 코딩 도메인에서는 검증 가능한 보상(verifiable reward)을 설계하기 상대적으로 용이하다 — 수학은 최종 답의 정오 판정, 코딩은 테스트 케이스 통과 여부를 자동으로 확인할 수 있다. 명령 수행 도메인은 더 복잡한데, 일반적으로 (1) 규칙 기반 보상(형식 준수, 길이 제약 등), (2) 학습된 보상 모델을 판정자로 사용, (3) LLM-as-judge 방식으로 다른 강력한 모델이 품질을 평가하는 접근이 사용된다. "Zero-shot RL"이라는 표현은 GRPO나 유사 알고리즘을 사용했을 가능성이 있다. (전문에서 구체적 보상 함수 설계 확인 필요)

**6.** MMLU 7B ~70%는 Llama 3.1 8B(약 69-73%)와 대등하며, 32B ~80%는 Qwen 2.5 32B(약 83%)보다 소폭 뒤처진다. 이 격차의 주요 원인은 학습 데이터의 규모와 품질 차이일 가능성이 가장 높다. Qwen과 Llama는 수십 조 토큰 규모의 독점 데이터를 활용하는 반면, OLMo 3는 완전 공개 데이터(DOLMA 3)만을 사용하므로 데이터 다양성과 품질에서 구조적 제약이 존재한다. 이는 "완전 공개" 원칙의 과학적 가치와 절대 성능 사이의 본질적 트레이드오프를 보여준다.

**7.** 장문 컨텍스트 추론과 함수 호출은 학습 데이터 수준에서 직접적 충돌이 크지 않으나, 멀티태스크 간섭은 SFT 단계에서 주로 발생한다. 일반적 대응 전략으로는 (1) 데이터 혼합 비율의 체계적 탐색, (2) 단계적 학습(먼저 일반 능력 → 이후 특화 능력 순차 학습)이 있다. OLMo 3의 4단계 파이프라인 자체가 이러한 간섭을 완화하는 설계로, 사전학습에서 일반 지식을 확보한 후 후반 단계에서 특화 능력을 점진적으로 추가하는 구조다.

[OctoThinker: Mid-training Incentivizes Reinforcement Learning Scaling](https://arxiv.org/abs/2506.20512)

Authors: Zengzhi Wang, Fan Zhou, Xuefeng Li, Pengfei Liu (Shanghai Jiao Tong University, GAIR Lab)

> Llama가 RL 추론 학습에서 Qwen보다 뒤처지는 이유는 수학적 기초 역량 부족이다. "Stable-then-Decay" 미드-트레이닝으로 Llama-3B를 Qwen2.5-3B와 동등하게 만들며, RL 스케일링을 위해서는 RL 자체보다 미드-트레이닝 데이터 품질이 더 중요함을 보인다.

- **Stable-then-Decay 2단계**: Stage 1(200B 토큰, 일정 LR) — MegaMath-Web-Pro-Max 72.5% 혼합으로 수학 기초 역량 주입; Stage 2(20B 토큰, 코사인 감쇠) — Long/Short/Hybrid 세 CoT 브랜치로 과제 형식 적응
- **데이터 품질이 지배적**: MegaMath-Web-Pro-Max → GSM8K +33.89%p, MATH500 +24.0%p; FineMath-4plus → 미미한 개선 — 점수 필터링보다 추론 밀도가 핵심
- **명령 추종 데이터의 역할**: 0.8B 토큰의 instruction-following 데이터가 Short-CoT 잠재력을 "해제"하고 훈련 안정화 — 추론 능력(what to think)과 지시 수행 능력(how to respond)은 독립적 차원
- **점진적 길이 스케줄러**: RL 단계에서 0-200스텝(2K) → 200-320스텝(4K) → 320-400스텝(8K) — 초기 희소 보상 문제를 해결하고 Long-CoT 불안정성을 커리큘럼으로 제어
- **미드-트레이닝 예산 단조 스케일링**: 20B→70B→100B 토큰으로 RL 성능 일관 향상 — Stable 단계만으로 10~20% 기본 향상 달성

## Follow-Up Questions

1. Llama와 Qwen 모델이 RL 추론 학습에서 서로 다른 동작을 보이는 근본 원인은 무엇이며, 미드-트레이닝이 이 격차를 해소하는 메커니즘은 무엇인가?

2. Stable-then-Decay 전략에서 Stage 1의 일정 학습률 구간이 200B 토큰으로 설정된 근거는 무엇이며, 이 비율이 모델 크기별로 달라져야 하는 이유는 무엇인가?

3. MegaMath-Web-Pro-Max가 FineMath-4plus 대비 압도적 성능 차이를 보이는 구체적인 데이터 특성 차이는 무엇인가?

4. Long-CoT 데이터가 성능 향상과 동시에 불안정성을 유발하는 트레이드오프를 Decay 단계의 브랜치 설계가 어떻게 완화하며, Hybrid 브랜치가 Long/Short 각각보다 우월한가?

5. 점진적 응답 길이 스케줄러(2K→4K→8K)가 RL 안정성에 기여하는 원리는 무엇이며, 이 스케줄이 단순히 처음부터 8K를 허용하는 것과 어떤 차이를 만드는가?

6. 명령 추종 데이터 0.8B 토큰이 Short-CoT의 잠재력을 "해제"한다는 발견은, 미드-트레이닝에서 추론 능력과 지시 수행 능력 사이의 어떤 상호작용을 시사하는가?

7. 이 Stable-then-Decay 미드-트레이닝 전략이 수학 추론 이외의 도메인(코드 생성, 과학 추론 등)에도 일반화될 수 있는가, 그리고 그 경우 어떤 요소를 변경해야 하는가?

## Answers

**1.** Llama 계열 모델은 사전학습 데이터 구성에서 수학적 추론 데이터의 비중이 Qwen 대비 상대적으로 낮아, RL로 추론 능력을 끌어올리려 할 때 기초 수학 역량 부족이 병목으로 작용한다. 미드-트레이닝은 이 격차를 메우는 "다리" 역할을 한다. 200B 토큰 규모의 수학 중심 코퍼스를 일정 학습률로 주입하면 모델의 내부 표현에 수학적 패턴 인식과 기본 추론 회로가 형성되어, 이후 GRPO 같은 RL 알고리즘이 탐색할 수 있는 정책 공간이 충분히 확보된다. RL은 이미 존재하는 약한 추론 능력을 강화하는 데 효과적이지, 추론 능력이 부재한 상태에서 이를 처음부터 생성하는 데는 비효율적이다.

**2.** Stage 1에서 200B 토큰의 일정 학습률 구간은 모델이 새로운 수학 도메인 지식을 충분히 흡수하되, 사전학습에서 획득한 일반 언어 능력을 급격히 잃지 않도록 하는 균형점이다. 모델 크기별로 학습률이 다른 것(1B: 5e-5, 3B: 2e-5, 8B: 1e-5)은 파라미터 수가 증가할수록 각 파라미터의 기울기 업데이트가 전체 모델에 미치는 영향이 누적적으로 커지기 때문이다. 큰 모델에 높은 학습률을 적용하면 catastrophic forgetting이나 학습 불안정이 발생할 위험이 높으므로, 모델 규모에 반비례하는 학습률 설정이 필요하다.

**3.** MegaMath-Web-Pro-Max는 73.8B 토큰 규모의 수학 추론 코퍼스로, 단순 수학 텍스트가 아닌 추론 과정이 포함된 고품질 웹 데이터를 큐레이션한 결과물이다. FineMath-4plus는 품질 필터링 점수 4 이상의 데이터를 사용하지만, 점수 기반 필터링만으로는 추론 과정의 명시성, 단계별 풀이의 완전성, 다양한 난이도 분포 등을 보장하지 못한다. MegaMath-Web-Pro-Max의 우월성은 데이터 "양"보다 "추론 밀도"와 "풀이 과정의 질"이 미드-트레이닝 효과를 좌우한다는 실용적 교훈을 준다.

**4.** Long-CoT 데이터(OpenR1, AM-DeepSeek-Distilled)는 긴 추론 체인을 통해 복잡한 문제 해결 패턴을 학습시키지만, 모델이 불필요하게 긴 응답을 생성하거나 추론 경로가 발산하는 부작용을 동반한다. Decay 단계의 브랜치 설계는 이 트레이드오프를 실험적으로 분리한다. OctoThinker-Long-3B가 RL 후 Qwen2.5-3B와 동등한 성능을 달성한 결과는 Long-CoT가 RL의 탐색 공간을 풍부하게 만들어 RL 스케일링 이점을 극대화함을 보여주며, 불안정성은 길이 스케줄러와 복잡한 프롬프트 템플릿으로 제어하는 전략을 취한다.

**5.** 점진적 응답 길이 스케줄러는 RL 초기 단계에서 모델이 짧은 추론 체인으로 쉬운 문제를 안정적으로 해결하는 패턴을 먼저 학습하게 한 뒤 점진적으로 더 긴 추론을 허용하는 커리큘럼 학습 전략이다. 처음부터 8K 토큰을 허용하면 롤아웃 16개 중 올바른 답에 도달하는 비율이 낮아 GRPO의 배치 내 상대적 보상 비교의 신뢰성이 떨어진다. 2K로 시작하면 보상 신호의 품질이 개선되어 초기 학습이 안정화되고, 이후 단계에서 더 복잡한 문제를 풀 기초가 마련된다.

**6.** 명령 추종 데이터 0.8B 토큰의 추가가 Short-CoT의 잠재력을 해제한다는 발견은, 미드-트레이닝된 모델이 수학적 지식은 갖추었으나 "질문에 대해 구조화된 형식으로 답하라"는 과제 수행 프레임워크가 부족할 수 있음을 보여준다. 명령 추종 데이터가 이 메타 능력을 제공함으로써 수학 지식이 실제 문제 풀이로 표현되는 경로가 열린다. 훈련 안정화 효과는 명령 추종 데이터가 일종의 정규화 역할을 하여 모델이 수학 도메인에 과적합되는 것을 방지하기 때문으로 추론된다.

**7.** Stable-then-Decay 전략의 핵심 원리는 "도메인 특화 기초 역량 주입 → 과제 형식 적응 → RL 강화"라는 파이프라인이므로 다른 도메인에도 이론적으로 일반화 가능하다. 그러나 몇 가지 변경이 필요하다. 첫째, Stage 1의 코퍼스를 해당 분야 고품질 추론 데이터(코드: 실행 가능한 코드+테스트; 과학: 실험 설계+검증 과정)로 교체해야 한다. 둘째, RL 보상 함수 설계가 달라져야 한다(코드: 테스트 통과율; 과학: 논리적 일관성). 셋째, 응답 길이 스케줄러의 단계별 설정도 도메인의 전형적 추론 길이에 맞춰 조정이 필요하다.

[RLEF: GROUNDING CODE LLMS IN EXECUTION FEEDBACK WITH REINFORCEMENT LEARNING](https://arxiv.org/abs/2410.02089)

Jonas Gehring, Kunhao Zheng, Jade Copet, Vegard Mella, Quentin Carbonneaux, Taco Cohen, Gabriel Synnaeve

> Large language models (LLMs) deployed as agents solve user-specified tasks over multiple steps while keeping the required manual engagement to a minimum. Crucially, such LLMs need to ground their generations in any feedback obtained to reliably achieve the desired outcomes. We propose an end-to-end reinforcement learning method for teaching models to leverage execution feedback in the realm of code synthesis, where state-of-the-art LLMs struggle to improve code iteratively compared to independent sampling. We benchmark on competitive programming tasks, where we achieve new state-of-the art results with both small (8B parameters) and large (70B) models while reducing the amount of samples required by an order of magnitude. Our analysis of inference-time behavior demonstrates that our method produces LLMs that effectively leverage automatic feedback over multiple steps.

## Follow-Up Questions

1. RLEF trains models to leverage execution feedback iteratively, whereas standard LLMs treat each code generation attempt independently. What specific failure modes of independent sampling does the iterative feedback loop address, and why can't chain-of-thought prompting alone solve these?

2. The paper trains on competitive programming tasks where execution feedback (pass/fail on test cases) is the reward signal. How might this training objective differ from real-world software engineering feedback, and what capabilities might be learned or not learned as a result?

3. What does it mean for a model to "ground its generations in feedback" — specifically, what must change in the model's internal representations or generation behavior compared to a model that ignores prior execution results?

4. The method achieves state-of-the-art results while "reducing samples required by an order of magnitude." What is the relationship between sample efficiency and the quality of feedback grounding, and how does RL training alter the inference-time sampling strategy?

5. Both 8B and 70B models show improvements from RLEF. Does the benefit scale proportionally with model size, and what does this imply about whether grounding in execution feedback is primarily a capability issue (needing more parameters) or a training objective issue?

6. The multi-conversation flow involves formatting execution feedback and querying for an update. How sensitive is the method to the quality of feedback formatting — would different feedback representations (e.g., error messages vs. stack traces vs. diff outputs) lead to significantly different learning outcomes?

7. What are the key limitations of using execution feedback as a sole reward signal — for instance, how does the method handle problems where code passes all provided test cases but is subtly incorrect, or where the test suite itself is incomplete?

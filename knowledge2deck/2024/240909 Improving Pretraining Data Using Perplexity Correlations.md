[Improving Pretraining Data Using Perplexity Correlations](https://arxiv.org/abs/2409.05816)

Authors: Tristan Thrush, Christopher Potts, Tatsunori Hashimoto

> LLM 손실(perplexity)과 다운스트림 벤치마크 성능 간의 상관관계를 이용해, 별도의 LLM 학습 없이 고품질 사전학습 데이터 도메인을 선택하는 프레임워크. Open LLM Leaderboard의 90개 공개 LLM을 "실험 대리자"로 활용한다.

- **핵심 아이디어**: 도메인 j의 perplexity가 낮은 모델일수록 다운스트림 벤치마크도 잘 한다면, 그 도메인 데이터는 고품질이다. 이 상관관계를 랭크 기반 계수 γj로 정량화한다.
- **Single-Index Model**: yi = f(⟨θ*, xi⟩ + εi) — 링크 함수 f는 미지의 단조함수, 데이터-손실 관계를 명시적으로 모델링할 필요 없음. Theorem 1이 일관성(consistency)을 보장한다.
- **160M 파라미터 성능**: DSIR 대비 평균 순위 1.750 vs. 4.500, 수작업으로 제작한 fastText 분류기와 동등한 성능을 무감독(unsupervised) 방식으로 달성.
- **스케일링 효과**: 1.4B까지 스케일 확장 시 개선 폭 증가 — 데이터 품질의 이점은 모델이 클수록 더 뚜렷하다.
- **수확체감 발견**: 사전 필터링된 데이터셋에서는 효과 감소 — 상관계수 신호는 원시 웹 크롤 데이터에서 가장 강하며, 이미 정제된 데이터에는 보완적 방법이 필요하다.

## Follow-Up Questions

1. 랭크 기반 상관계수(γj)가 Pearson 상관계수 대신 채택된 이유는 무엇이며, 이 선택이 도메인 가중치 추정의 강건성에 어떤 영향을 미치는가?

2. 90개 공개 LLM의 이질성(아키텍처, 학습 데이터, 규모 차이)이 Single-Index Model의 가정을 위반할 가능성은 없는가, 그리고 이를 어떻게 완화하는가?

3. fastText 분류기를 페이지 수준 필터링에 사용하는 단계에서 도메인 수준 상관계수 신호가 어떻게 페이지 단위로 전이되며, 이 과정에서 정보 손실이 발생하는가?

4. 사전 필터링된 데이터셋에서 관찰된 수확체감 현상의 원인은 무엇이며, 이것이 본 방법론의 실용적 적용 범위에 대해 시사하는 바는 무엇인가?

5. Theorem 1의 가우시안 가정이 실제 웹 도메인 데이터 분포에서 얼마나 현실적이며, 이 가정이 깨질 때 추정기의 성능은 어떻게 변하는가?

6. 160M에서 1.4B로 스케일링할 때 개선 폭이 증가하는 패턴이 더 큰 모델(7B, 70B)에서도 지속될 것으로 기대할 수 있는가, 그리고 그 근거는 무엇인가?

7. 본 프레임워크의 도메인 가중치 추정이 벤치마크 선택에 민감한가 — 즉, Open LLM Leaderboard 대신 다른 평가 체계를 사용하면 선택되는 데이터 분포가 크게 달라지는가?

## Answers

**1.** 랭크 기반 상관계수는 모델 손실과 다운스트림 성능 간의 관계가 단조적(monotonic)이기만 하면 유효하며, 선형성을 요구하지 않는다. 이는 Single-Index Model에서 링크 함수 f가 미지의 비선형 함수일 수 있다는 설정과 정확히 부합한다. Pearson 상관계수는 선형 관계만 포착하므로, 로그 스케일의 perplexity와 정확도 기반 벤치마크 점수 사이에 비선형 단조 관계가 존재할 경우 신호를 과소추정할 수 있다. 또한 랭크 변환은 이상치(outlier) 모델의 영향을 자동으로 억제하여, 90개라는 비교적 적은 모델 수에서도 추정의 강건성을 확보한다. Theorem 1이 이 랭크 기반 추정기의 일관성을 가우시안 가정 하에서 증명한 것은, 비선형 f를 명시적으로 복구하지 않고도 도메인 가중치 방향을 식별할 수 있음을 보장하는 핵심 결과다.

**2.** 90개 모델의 이질성은 오히려 방법론의 강점이 될 수 있다. Single-Index Model은 모든 모델이 동일한 도메인 가중치 벡터 θ*에 의해 설명된다고 가정하는데, 이는 "특정 도메인에서의 손실 감소가 다운스트림 성능 향상으로 이어지는 방향"이 모델 간에 공유된다는 것이다. 다양한 아키텍처와 규모의 모델이 이 패턴을 일관되게 보인다면, 추정된 θ*는 특정 모델 패밀리에 과적합되지 않는 일반적 신호를 포착한다. 학습 데이터가 크게 다른 모델(예: 코드 특화 vs. 대화 특화)은 잡음원으로 작용할 수 있으나, 랭크 기반 추정기의 이상치 강건성과 충분한 모델 수에 의한 평균화 효과로 부분적으로 완화된다.

**3.** 도메인 수준 상관계수는 "이 도메인의 데이터가 다운스트림 성능에 긍정적인가"라는 거시적 신호를 제공하고, fastText 분류기는 이 신호를 페이지 단위로 구체화하는 역할을 한다. 상관계수가 높은 도메인의 페이지들을 양성 예시로, 낮은 도메인의 페이지들을 음성 예시로 사용해 fastText를 학습시킨다. 동일 도메인 내 페이지 간 품질 편차가 정보 손실을 야기할 수 있으나, fastText는 텍스트의 n-gram 특징을 학습하므로 고품질 텍스트의 표면적 패턴(어휘 수준, 문장 구조 등)을 포착해 도메인 경계를 넘어 일반화할 수 있다. 논문에서 이 파이프라인이 수동 제작 fastText 분류기와 동등한 성능을 달성한 것은 이 전이가 실질적으로 작동함을 시사한다.

**4.** 수확체감은 사전 필터링이 이미 가장 명백한 저품질 데이터를 제거했기 때문에 발생한다. 상관계수 기반 신호는 "좋은 도메인 vs. 나쁜 도메인"의 대비에서 가장 강한 식별력을 가지는데, 사전 필터링된 데이터셋에서는 이 대비가 약화되어 남은 도메인들 간의 상관계수 차이가 줄어든다. 실용적으로 이는 본 방법이 원시(raw) 웹 크롤 데이터에 가장 큰 가치를 제공하며, 다단계 필터링 파이프라인에서 초기 단계에 배치하는 것이 최적임을 의미한다.

**5.** Theorem 1의 가우시안 가정은 현실의 웹 도메인 데이터에서 근사적이다. 도메인별 손실 분포는 긴 꼬리(heavy tail)를 가지거나 다봉(multimodal) 구조를 보일 수 있다. 그러나 랭크 기반 추정기는 분포의 구체적 형태보다 순서 관계에 의존하므로, 정규성 위반에 대해 Pearson 기반 방법보다 본질적으로 강건하다. 가우시안 가정이 심하게 깨지는 경우 추정기의 수렴 속도가 느려질 수 있으나, 일관성 자체는 단조 링크 함수의 존재만으로도 유지될 가능성이 높다. 실험 결과가 이론적 예측과 잘 부합하는 것은 이 근사가 실질적으로 충분함을 시사한다.

**6.** 160M에서 1.4B로의 개선 폭 증가는 데이터 품질의 영향이 모델 용량이 커질수록 더 뚜렷해진다는 기존 스케일링 법칙 연구와 일치한다. 7B, 70B에서도 개선이 지속될 것으로 기대할 수 있으나 두 가지 불확실성이 존재한다. 첫째, 상관계수 추정에 사용된 90개 모델의 분포가 대형 모델의 학습 동역학을 충분히 반영하는지 불명확하다. 둘째, 대형 모델에서는 데이터 양 자체가 더 중요해지므로 공격적 필터링으로 인한 데이터 감소가 개선을 상쇄할 수 있다. 1.4B를 넘어서는 스케일링 검증은 계산 비용의 현실적 제약으로 남아 있는 열린 질문이다.

**7.** 도메인 가중치 θ*는 "이 도메인이 *특정 벤치마크 집합*의 성능과 얼마나 상관되는가"를 인코딩하므로, 벤치마크가 바뀌면 θ*도 달라진다. 예컨대 코딩 벤치마크를 타겟으로 하면 GitHub 관련 도메인의 가중치가 높아지고, 상식 추론 벤치마크를 타겟으로 하면 백과사전적 도메인이 선호된다. 이는 약점이 아니라 의도된 유연성으로 볼 수 있다 — 목표 능력에 맞춰 벤치마크를 선택하면 데이터 선택이 자동으로 조정된다. Open LLM Leaderboard를 사용한 것은 범용성을 위한 합리적 선택이나, 특정 응용(의료, 법률 등)을 목표로 할 때는 해당 도메인 벤치마크로 상관계수를 재추정하는 것이 필수적이다.

[daVinci-Dev: Agent-native Mid-training for Software Engineering](https://arxiv.org/abs/2601.18418)

Authors: Ji Zeng, Dayuan Fu, Tiantian Mi, Yumin Zhuang, Yaxing Huang, Xuefeng Li, Lyumanshan Ye, Muhang Xie, Qishuo Hua, Zhen Huang, Mohan Jiang, et al.

> 값비싼 RL 없이 실제 개발 워크플로우를 반영하는 "에이전트 네이티브 데이터"에 대한 미드-트레이닝만으로 SWE-bench Verified 58.5%(72B)를 달성한다. 핵심은 정적 학습 데이터와 동적 개발 환경 간의 분포 불일치를 미드-트레이닝 단계에서 직접 해소하는 것이다.

- **두 가지 에이전트 네이티브 데이터 유형**: Contextually-native(완전한 정보 흐름 보존 — 파일 구조·히스토리·관련 코드 포함) + Environmentally-native(실행 가능 리포지토리에서 실제 도구 호출 포함 궤적) — 전자가 "무엇을 봐야 하는가", 후자가 "어떻게 행동해야 하는가"를 담당
- **토큰 효율**: 73.1B 미드-트레이닝 토큰으로 Kimi-Dev(~150B 토큰, 60.4%) 대비 절반 이하 토큰 사용 — 에이전트 특화 데이터 구성이 일반 코드 데이터 대량 투입보다 토큰 당 학습 신호 밀도를 높임
- **스케일링 결과**: 32B → 56.1%, 72B → 58.5%; 완만한 향상은 현재 성능 병목이 모델 용량보다 에이전트 전략의 질에 있음을 시사
- **분포 불일치 해소**: 입출력 형식뿐 아니라 상호작용의 시간적 구조(temporal structure)까지 학습 분포에 포함 — 추론 시 환경 피드백에 대한 자연스러운 적응 가능
- **두 포스트-트레이닝 설정에서 우수성**: 정렬된 기반 모델 기준으로 일관된 개선 — RL 추가 시 시너지 가능성 내포

## Follow-Up Questions

1. Contextually-native trajectories와 environmentally-native trajectories를 분리하여 정의한 이유는 무엇이며, 두 유형의 데이터가 모델 성능에 기여하는 메커니즘은 어떻게 다른가?

2. 73.1B 토큰의 미드-트레이닝만으로 Kimi-Dev(~150B 토큰) 대비 경쟁력 있는 성능을 달성한 핵심 요인은 데이터 효율성인가, 아니면 데이터 구성(composition)의 질적 차이인가?

3. 정적 학습 데이터와 동적 개발 환경 간의 분포 불일치(distribution mismatch) 문제를 구체적으로 어떤 메커니즘으로 완화하며, 이 접근이 기존 domain adaptation 기법과 어떻게 구별되는가?

4. RL 기반 포스트-트레이닝 없이 미드-트레이닝만으로 56.1~58.5%를 달성했다면, 여기에 RL을 추가했을 때의 성능 상한은 어디까지이며, 미드-트레이닝과 RL의 상호작용은 어떤 양상을 보이는가?

5. Environmentally-native trajectories 수집 시 실행 가능한 리포지토리에서의 도구 호출 데이터를 어떻게 품질 필터링하며, 실패한 궤적(failed trajectories)은 훈련에 포함하는가 배제하는가?

6. 32B에서 72B로의 스케일링에서 SWE-bench Verified 성능 향상이 56.1%에서 58.5%로 비교적 완만한데, 이는 미드-트레이닝 데이터의 스케일링 법칙이 모델 파라미터 크기보다 데이터 품질에 더 민감함을 시사하는가?

7. 이 미드-트레이닝 프레임워크를 소프트웨어 엔지니어링 이외의 에이전트 태스크(예: 웹 브라우징, 과학 실험 자동화)로 일반화할 때, contextually-native와 environmentally-native 데이터의 정의는 어떻게 재구성되어야 하는가?

## Answers

**1.** 두 유형의 분리는 에이전트 행동의 서로 다른 역량 축을 타겟팅한다. Contextually-native trajectories는 에이전트가 올바른 정보를 올바른 시점에 참조하는 능력 — 코드베이스의 구조적 이해와 관련 컨텍스트 선별 능력 — 을 학습시킨다. 이는 실제 개발에서 개발자가 파일 구조, 커밋 히스토리, 의존성 그래프를 탐색하며 문제를 파악하는 과정에 대응한다. 반면 environmentally-native trajectories는 도구 호출의 정확한 시퀀싱과 런타임 피드백 해석 능력을 학습시킨다. 전자가 "무엇을 봐야 하는가"를 가르친다면, 후자는 "어떻게 행동해야 하는가"를 가르치며, 이 두 축의 결합이 완전한 에이전트 역량을 구성한다.

**2.** 토큰 수 대비 성능 효율의 핵심은 데이터의 질적 구성에 있을 가능성이 높다. 일반적인 코드 사전학습 데이터에는 에이전트 행동과 무관한 정보(단순 코드 스니펫, 문서, 주석 등)가 상당 비율을 차지하지만, daVinci-Dev의 미드-트레이닝 데이터는 컨텍스트 탐색-도구 호출-결과 해석이라는 에이전트 특화 패턴으로 구성되어 있다. 이는 instruction tuning에서 데이터 큐레이션이 데이터 양보다 중요하다는 기존 연구 결과와 일맥상통하며, 동일 토큰 예산에서 더 높은 태스크 관련 학습 신호 밀도를 달성한다.

**3.** 분포 불일치 문제의 핵심은, 기존 사전학습 데이터가 정적 텍스트(코드 파일, 문서)인 반면 실제 에이전트 운영 시에는 동적 환경 피드백(테스트 출력, 에러 로그, 파일 시스템 변화)을 처리해야 한다는 점이다. daVinci-Dev는 이를 미드-트레이닝 단계에서 실제 환경 상호작용 데이터를 직접 학습 분포에 포함시키는 방식으로 해결한다. 기존 domain adaptation이 주로 타겟 도메인의 텍스트 분포를 맞추는 데 집중하는 반면, 이 접근은 입출력 형식뿐 아니라 상호작용의 시간적 구조(temporal structure)까지 맞춘다는 점에서 차별화된다.

**4.** 일반적으로 미드-트레이닝은 모델의 기반 역량을 확장하고, RL은 특정 보상 신호에 대한 행동 최적화를 수행하므로 상호 보완적이다. 강력한 미드-트레이닝 기반 위의 RL은 탐색 효율성이 높아져 더 적은 RL 스텝으로도 높은 성능에 도달할 수 있다. 다만 32B에서 72B로의 완만한 성능 증가를 고려하면, 현재 성능 병목이 모델 용량보다는 평가 벤치마크의 특성이나 데이터 커버리지에 있을 수 있어, RL 추가의 한계 효용도 이 요인에 의해 제약될 수 있다.

**5.** 구체적인 필터링 파이프라인은 전문 확인이 필요하나, 일반적인 에이전트 궤적 데이터 합성에서는 최종 결과의 정확성(테스트 통과 여부)을 기준으로 성공 궤적만 선별하는 outcome filtering이 표준적이다. 그러나 실패 궤적에도 학습 신호가 존재한다 — 에러 진단 후 수정하는 패턴, 잘못된 접근을 포기하고 대안을 시도하는 패턴 등은 실제 개발자 행동의 핵심이다. "Environmentally-native"라는 명명이 실제 환경 상호작용의 충실성을 강조하는 만큼, 자기 수정(self-correction) 패턴도 포함했을 가능성이 있으며 이는 최근 반성(reflection) 데이터 연구 흐름과도 부합한다.

**6.** 32B에서 72B로 2.25배의 파라미터 증가에서 2.4%p의 성능 향상은 파라미터 스케일링의 수확 체감을 시사한다. 두 가지 해석이 가능하다. 첫째, SWE-bench Verified에서 56~58% 구간의 문제들이 모델 크기보다는 에이전트 전략의 질에 더 의존하는 유형일 수 있다. 둘째, 미드-트레이닝 데이터가 73.1B로 고정된 상태에서 모델만 키우면 데이터 대비 모델이 과대해져 미드-트레이닝 이득이 줄어들 수 있다 — Chinchilla 관점에서 72B 모델에는 미드-트레이닝 데이터도 비례적으로 확대해야 최적 성능에 도달함을 암시한다.

**7.** 일반화를 위해서는 두 데이터 유형의 추상적 정의를 태스크에 맞게 재해석해야 한다. Contextually-native data는 "에이전트가 의사결정에 필요한 배경 정보의 완전한 흐름"으로 재정의될 수 있다. 웹 브라우징에서는 페이지 DOM 구조, 네비게이션 히스토리, 현재 페이지의 시맨틱 컨텍스트가 이에 해당하고, 과학 실험 자동화에서는 실험 프로토콜, 선행 결과, 장비 상태 정보가 된다. Environmentally-native data는 "실제 환경의 상태 변화와 피드백을 포함한 행동 기록"으로 재정의된다. 핵심 원칙은 동일하다: 정적 지식과 동적 환경 상호작용의 간극을 미드-트레이닝 데이터로 메우는 것이다.

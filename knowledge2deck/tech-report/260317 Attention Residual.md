[Attention Residual](https://github.com/MoonshotAI/Attention-Residuals/blob/master/Attention_Residuals.pdf)

Authors: Kimi Team

> Residual connections [12] with PreNorm [60] are standard in modern LLMs, yet they accumulate all layer outputs with fixed unit weights. This uniform aggregation causes uncontrolled hidden-state growth with depth, progressively diluting each layer’s contribution [27]. We propose Attention Residuals (AttnRes), which replaces this fixed accumulation with softmax attention over preceding layer outputs, allowing each layer to selectively aggregate earlier representations with learned, input-dependent weights. To address the memory and communication overhead of attending over all preceding layer outputs for large-scale model training, we introduce Block AttnRes, which partitions layers into blocks and attends over block-level representations, reducing the memory footprint while preserving most of the gains of full AttnRes. Combined with cache-based pipeline communication and a two-phase computation strategy, Block AttnRes becomes a practical drop-in replacement for standard residual connections with minimal overhead. Scaling law experiments confirm that the improvement is consistent across model sizes, and ablations validate the benefit of content-dependent depth-wise selection. We further integrate AttnRes into the Kimi Linear architecture [69] (48B total / 3B activated parameters) and pre-train on 1.4T tokens, where AttnRes mitigates PreNorm dilution, yielding more uniform output magnitudes and gradient distribution across depth, and improves downstream performance across all evaluated tasks.
## Follow-Up Questions

1. Standard residual connections accumulate all layer outputs with fixed unit weights, causing "uncontrolled hidden-state growth with depth." Why does this growth dilute each layer's contribution — is this a problem of scale, direction, or both — and why does it become progressively worse with more layers?

2. AttnRes replaces fixed residual accumulation with softmax attention over preceding layer outputs, giving each layer "input-dependent weights" over earlier representations. What computational analogy does this draw with inter-token attention, and why is the depth-wise selection benefit expected to be independent of the token-level attention already in the model?

3. Full AttnRes requires attending over all preceding layer outputs, which is memory-intensive. Block AttnRes groups layers and attends over block-level representations instead. What information is lost by this blocking, and how do you choose the optimal block size to balance memory cost against quality retention?

4. AttnRes is motivated by "PreNorm dilution" — the observation that PreNorm+residual connections cause magnitudes to become non-uniform with depth. Why does this magnitude non-uniformity affect model quality, and does AttnRes fix the root cause or only the symptom?

5. The paper validates AttnRes through scaling law experiments, claiming "consistent improvement across model sizes." What is the scaling exponent change introduced by AttnRes — does it shift the loss-compute tradeoff curve, or primarily improve the intercept at all scales?

6. AttnRes is integrated into the Kimi Linear architecture (48B total / 3B active parameters). How does the combination of MoE sparse activation and depth-wise attention residuals interact — could the selective expert activation create additional training instability or routing collapse when combined with AttnRes?

7. What are the failure modes or edge cases for AttnRes — for instance, are there training scenarios (very deep networks, specific learning rate schedules, or data types) where attending over preceding layers could cause instability, gradient issues, or degenerate attention patterns?

## Answers

**1.** With standard residual connections, the hidden state at layer L is the sum of all previous layer outputs: h_L = h_0 + delta_1 + delta_2 + ... + delta_L. As depth increases, the magnitude of h_L grows proportionally to the number of layers (assuming each delta_i contributes O(1)), meaning earlier layer representations increasingly represent a small fraction of the total state. This causes magnitude dilution: each individual layer's output delta_i is divided by the total accumulated magnitude when computing normalized representations, progressively reducing its relative influence. The problem is both scale (the magnitude of h_L grows) and direction (the direction of h_L is increasingly determined by the sum of all deltas rather than any individual layer's contribution), and it worsens with depth because each additional layer adds one more term to an already-large sum without compensating normalization.

**2.** AttnRes performs softmax-weighted aggregation over the outputs of all preceding layers, where the weights are computed as a dot product between the current layer's query representation and the key representations of preceding layer outputs — directly analogous to how token-level attention aggregates value representations from the sequence context. The depth-wise selection benefit is expected to be independent of token-level attention because they operate on different dimensions: token attention operates across the sequence dimension (selecting which past tokens to attend to), while AttnRes operates across the depth dimension (selecting which past layer representations to incorporate). These two selection mechanisms are orthogonal — the depth-wise weights determine which level of abstraction to build upon at each layer, while token-level weights determine which positions in the sequence to aggregate information from.

**3.** Block AttnRes loses the fine-grained cross-layer interactions that full AttnRes captures: within a block, the model still accumulates layer outputs with fixed weights, so the dilution problem reappears within blocks. At block boundaries, the model can selectively attend over block-level representations, correcting for cross-block dilution but not intra-block dilution. The optimal block size trades memory/communication cost against intra-block dilution: smaller blocks (e.g., 2-4 layers) capture more of the benefit of full AttnRes at higher memory cost, while larger blocks (e.g., 8-16 layers) reduce memory cost but allow more intra-block dilution. In practice, block size is determined by the point at which intra-block dilution becomes significant — typically when individual layer contributions within a block are diluted below a threshold — and by hardware constraints (cache sizes, communication bandwidth in pipeline-parallel training).

**4.** Magnitude non-uniformity affects model quality because it creates heterogeneous gradient flow across depth: layers contributing smaller relative magnitudes to the residual stream receive smaller gradient signals, potentially causing them to underfit or converge slowly relative to earlier layers. Additionally, magnitude variation makes the effective learning rate implicitly different across layers (layers with larger-magnitude contributions effectively have their updates amplified relative to the final loss), causing some layers to be implicitly over- or under-trained. AttnRes addresses both the root cause and the symptom: the root cause is the unweighted accumulation, which AttnRes replaces with learned, input-dependent weights; the symptom is magnitude non-uniformity, which the learned weights can correct by downweighting high-magnitude early layers and upweighting low-magnitude recent ones.

**5.** Scaling law experiments in the paper suggest AttnRes primarily improves the intercept (loss at a given compute budget) rather than shifting the scaling exponent. This means AttnRes makes models more efficient — they achieve lower loss for the same FLOPs — but doesn't fundamentally change how performance scales with compute. Intuitively, this is expected: AttnRes is an architectural improvement to how information flows through a fixed-depth model, not a change in the functional form of the model's capacity utilization. A shift in scaling exponent would imply that deeper models benefit proportionally more from AttnRes, which would be a more dramatic finding. The consistent improvement across model sizes without increasing the exponent supports the interpretation that AttnRes is a reliable but bounded architectural improvement.

**6.** The combination of MoE sparse activation and AttnRes creates a potential training instability: in MoE, only a subset of experts are active for any given token, meaning the per-token residual stream is shaped by a sparse set of expert outputs. When AttnRes attends over preceding layer outputs to compute depth-wise weights, it operates on representations that were produced by different expert subsets for different tokens, potentially creating inconsistent depth-wise attention patterns where the "effective depth" varies by token (depending on which experts were activated). This could complicate the model's learning of stable depth-wise aggregation patterns. Additionally, expert routing collapse — where the MoE converges to using only a few experts — could create degenerate block-level representations that confuse AttnRes's depth-wise aggregation, though the paper reports positive results suggesting these instabilities are manageable in practice.

**7.** AttnRes failure modes include: (a) degenerate attention patterns where the depth-wise attention collapses to always attending only to the immediately preceding layer or always attending uniformly, degenerating to either a fixed residual connection or uniform averaging; this could occur with very high learning rates that cause the attention logits to become extreme, or with poor initialization of the depth-wise query/key projections. (b) Gradient instability in very deep networks where backpropagating through the attention over preceding layers creates long gradient paths that amplify or explode gradients for early layers — specifically, the gradient path from loss through AttnRes reaches layer 1's output via the full depth-wise attention computation, creating O(depth) gradient paths similar to vanilla RNNs before gradient clipping. (c) For data types with very high sequence-to-sequence variability (e.g., code vs. natural language in a mixed training corpus), the input-dependent depth-wise weights may not stabilize across data types, causing inconsistent aggregation behavior that hurts performance on some modalities while helping others.

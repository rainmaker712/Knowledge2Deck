[NVIDIA Nemotron Nano 2: An Accurate and Efficient Hybrid Mamba-Transformer Reasoning Model](https://arxiv.org/abs/2508.14444)

> We introduce Nemotron-Nano-9B-v2, a hybrid Mamba-Transformer language model designed to increase throughput for reasoning workloads while achieving state-of-the-art accuracy compared to similarly-sized models. Nemotron-Nano-9B-v2 builds on the Nemotron-H architecture, in which the majority of the self-attention layers in the common Transformer architecture are replaced with Mamba-2 layers, to achieve improved inference speed when generating the long thinking traces needed for reasoning. We create Nemotron-Nano-9B-v2 by first pre-training a 12-billion-parameter model (Nemotron-Nano-12B-v2-Base) on 20 trillion tokens using an FP8 training recipe. After aligning Nemotron-Nano-12B-v2-Base, we employ the Minitron strategy to compress and distill the model with the goal of enabling inference on up to 128k tokens on a single NVIDIA A10G GPU (22GiB of memory, bfloat16 precision). Compared to existing similarly-sized models (e.g., Qwen3-8B), we show that Nemotron-Nano-9B-v2 achieves on-par or better accuracy on reasoning benchmarks while achieving up to 6x higher inference throughput in reasoning settings like 8k input and 16k output tokens. We are releasing Nemotron-Nano-9B-v2, Nemotron-Nano12B-v2-Base, and Nemotron-Nano-9B-v2-Base checkpoints along with the majority of our pre- and post-training datasets on Hugging Face.

## Follow-Up Questions

1. Nemotron-Nano-9B-v2 replaces "the majority of self-attention layers" with Mamba-2 layers. Why does this substitution improve throughput specifically for long reasoning traces, and what are the theoretical differences in how Mamba-2 handles long sequences compared to standard attention?

2. The model is pre-trained as 12B parameters and then compressed to 9B using the Minitron strategy. What does Minitron compression involve, and how does post-training compression compare to training a 9B model directly from scratch in terms of final performance and efficiency?

3. The training uses an FP8 training recipe on 20 trillion tokens. What numerical stability challenges arise when training hybrid Mamba-Transformer models in FP8, and how does the Mamba state-space model component behave differently from attention layers under reduced precision?

4. The model achieves up to 6x higher inference throughput compared to Qwen3-8B on long reasoning workloads (8k input + 16k output). Is this speedup attributable primarily to the Mamba architecture, the Minitron compression, or both — and how would you isolate each contribution experimentally?

5. The ability to run 128k token context on a single A10G GPU (22GiB) is a stated design goal. What architectural and quantization decisions enable this memory efficiency, and what are the accuracy trade-offs of fitting such long contexts into constrained memory?

6. The model is released alongside "the majority of pre- and post-training datasets." What motivates partial rather than full dataset release, and how does incomplete data transparency affect reproducibility and community trust in reported benchmark results?

7. What are the known failure modes of hybrid Mamba-Transformer models compared to pure Transformer models — specifically, in what types of tasks does replacing attention with Mamba layers most hurt performance, and has Nemotron-Nano-9B-v2 found effective mitigations?

## Answers

**1.** Mamba-2 improves throughput for long reasoning traces because it is a selective state-space model (SSM) with linear-time inference complexity: the recurrent computation during generation processes each token in O(1) with a fixed-size state, rather than attention's O(n) per-step cost that requires attending back over the entire context. For long output sequences (like extended reasoning chains with 16k output tokens), attention's KV cache grows linearly with generated tokens, requiring increasingly more memory and compute per step, while Mamba-2's fixed state size means constant memory and compute per step regardless of how long the generation has proceeded. Theoretically, Mamba-2 uses selective scan operations that allow the state to learn which information to retain or forget, giving it a form of adaptive memory compression that attention achieves only through explicit key-value caching.

**2.** Minitron compression is a structured pruning and knowledge distillation strategy: the 12B base model has specific components (attention heads, MLP hidden dimensions, or entire layers) pruned based on importance scores, and the resulting smaller model is then fine-tuned to recover performance by distilling knowledge from the original 12B model. Compared to training a 9B model from scratch, Minitron compression typically yields better performance for the same parameter count because: (a) the 12B model has already learned rich representations over 20T tokens which the distillation process transfers to the smaller model, and (b) training from scratch requires the model to learn everything anew, which is less efficient than distilling from a capable teacher. The trade-off is that Minitron requires first training the large model (which costs more total compute), making it more expensive than direct training but more effective for the final 9B model quality.

**3.** FP8 training of hybrid Mamba-Transformer models introduces specific numerical challenges. Mamba-2's state-space model recurrence involves sequential matrix multiplications that accumulate small numerical errors over the recurrent scan — in FP8's limited dynamic range (compared to BF16 or FP16), these accumulated errors can cause the hidden state to saturate or underflow, particularly for long sequences where the recurrence runs for many steps. The selective gating mechanism in Mamba-2 involves sigmoid and softmax-like operations that are sensitive to numerical precision since small differences in the gate values determine what information is retained or discarded. Attention layers, by contrast, have known FP8 stability solutions (e.g., attention logit clamping, per-token scaling); applying similar per-step state normalization to Mamba's recurrent state is needed but less standardized.

**4.** The 6x throughput improvement is attributable primarily to the Mamba architecture, not compression. The key driver is that replacing most attention layers with Mamba eliminates the KV cache growth bottleneck: during autoregressive generation of 16k output tokens, each Mamba layer operates at constant memory and compute while each attention layer's KV cache grows by 16k entries, making the latter increasingly bottlenecked by memory bandwidth. Minitron compression contributes a parameter-count reduction (12B to 9B, roughly 25%) which provides a secondary throughput improvement through reduced memory footprint and faster matrix multiplications, but the dominant factor is architectural. To isolate each contribution experimentally, you would benchmark: (a) the original 12B hybrid model, (b) a 9B dense transformer with equivalent compression, and (c) Nemotron-Nano-9B-v2, comparing throughput at identical long-context generation settings.

**5.** The memory efficiency for 128k context on a 22GiB A10G comes from two key factors: the Mamba architecture's fixed-size state (which does not grow with context length, unlike a KV cache that grows as O(context_length * num_attention_layers * hidden_dim)), and BF16 precision inference. The few retained attention layers do maintain a KV cache, but since "the majority" of layers are Mamba, this KV cache is a fraction of what a full transformer would require. The accuracy trade-off of extreme context compression is that Mamba's fixed state must summarize very long contexts into a finite state vector — information from very early positions in a 128k context may be over-compressed or lost, particularly for tasks requiring exact retrieval of early content. The paper notes reasoning improvements but precise behavior on content retrieval at extreme positions (early tokens in 128k contexts) may degrade compared to full attention.

**6.** The "majority but not all" dataset release reflects a common tension between scientific openness and practical constraints in large-scale industry research. Motivations for withholding some data include: (a) third-party data licensing restrictions that prevent redistribution; (b) proprietary synthetic data pipelines that represent competitive intellectual property; and (c) data quality filtering decisions that the team is not ready to fully document. Incomplete data transparency does affect reproducibility — external researchers cannot fully replicate results and must trust the reported numbers rather than independently verifying them. For community trust, partial release is better than no release but still creates an asymmetry: researchers building on Nemotron-Nano-9B-v2 cannot audit whether specific dataset choices introduce biases or limitations that would affect their use cases.

**7.** The known failure modes of hybrid Mamba-Transformer models compared to pure Transformers center primarily on tasks requiring precise long-range exact retrieval: when a specific token value from early in a long context must be reproduced verbatim, Mamba's compressed recurrent state may not preserve sufficient fidelity. Tasks where replacing attention with Mamba most hurts performance include: (a) needle-in-a-haystack retrieval where a specific piece of information must be retrieved from an arbitrary position in a long context; (b) tasks requiring tracking of multiple distinct entities over long ranges simultaneously; and (c) tasks with complex cross-position dependencies that require precise attention patterns. Nemotron-H addresses this by retaining a subset of full attention layers (a hybrid architecture) specifically to preserve exact retrieval capabilities for positions where the Mamba state cannot provide sufficient recall, with the retained attention layers concentrated to cover the cases where SSM compression most degrades performance.
